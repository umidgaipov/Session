# План реализации мобильной тестовой платформы «Quiet Confidence»

> **Цель:** Разработать легковесный, премиальный и ориентированный на смартфоны веб-интерфейс для базы тестов по экономической статистике (95 ситуационных кейсов + 57 практических задач) без лишнего визуального шума, со встроенным сохранением прогресса и автоматическим деплоем на GitHub Pages с кастомным доменом.
> **Референс стиля:** [docs/DESIGN.md](file:///d:/projects/Session/docs/DESIGN.md) («Quiet Confidence») и референс [mysite](file:///D:/projects/mysite).

---

## Этап 1. Архитектура, дизайн-система и Mobile-First каркас

*Фокус этапа: создание премиальной монохромной дизайн-системы в духе Apple и Linear, адаптивная верстка с нулевым горизонтальным скроллом и комфортной сенсорной эргономикой под смартфоны.*

### Шаг 1.1. Базовая структура и токены дизайн-системы
- **Стек:** Нативный стек без тяжелых фреймворков (чистый HTML5, модульный CSS3 с переменными, современный Vanilla JS / ES-модули), обеспечивающий мгновенную загрузку (<100ms) на любом мобильном интернете.
- **Цветовая палитра, фирменная сетка и типографика:**
  - Базовый фон: теплый благородный `Warm White` (`#FAFAF8`), карточки: чистый `White` (`#FFFFFF`) с ультратонкой границей (`#ECECEC`).
  - **Фирменные «квадратики» (Ambient Grid Background):** как в референсе `mysite` (`body::before` с `linear-gradient` сеткой 44px × 44px, цвет линий `rgba(0, 0, 0, 0.05..0.065)`), создающий тактильную глубину инженерного минимализма.
  - Текст и акценты: глубокий `Almost Black` (`#1A1A1A`) и нейтральный серый (`#6B6B6B`). Никаких кислотных градиентов и тяжелых теней.
  - Шрифт: **Inter** с выверенной оптической иерархией, плотным трекингом в заголовках и просторным межстрочным интервалом (1.6–1.7) для комфортного чтения условий задач.
- **Премиальный минимализм:** полное отсутствие звуковых эффектов, мигающих бейджей и навязчивой геймификации. Интерфейс — чистый, строгий и сфокусированный на содержании.

### Шаг 1.2. Сенсорная эргономика и мобильные компоненты
- **Mobile-First верстка (320px – 430px+):**
  - Ограничение ширины контентного блока (`max-width: 680px`), боковые отступы `16–20px`, безопасные зоны для экранов с вырезами (`safe-area-inset-*`).
  - Гарантированный **Zero Horizontal Scroll** для всех табличных данных, списков и математических выражений.
- **Компонентная база:**
  - **Header:** минималистичный статус-бар с логотипом/названием, переключателем категорий тестов и счетчиком решенных заданий.
  - **Карточка вопроса:** тег типа теста, блок контекста (`condition`/`situation`), четко выделенный вопрос.
  - **Варианты ответа:** крупные интерактивные плашки с минимальной высотой кликабельной зоны **48–56px** (стандарт Apple Human Interface Guidelines) для безошибочного тапа пальцем на ходу.

## Этап 2. Движок тестов, разбор ловушек и прогресс (LocalStorage)

*Фокус этапа: быстрая работа с базой из 152 вопросов, интерактивная проверка решений, детализированный разбор дистракторов и сохранение каждого действия в памяти браузера.*

### Шаг 2.1. Загрузка данных и навигация по каталогу тестов
- **Обработка данных:**
  - Прямое подключение подготовленных данных: `situational_tests.json` (95 вопросов) и `practical_tests.json` (57 расчетных задач).
  - Быстрое сегментированное переключение между режимами: «Ситуационные тесты» и «Практические расчеты».
- **Навигация и фильтрация:**
  - Свайп/кнопки перехода к следующему/предыдущему вопросу («Назад» / «Далее»).
  - Шторка быстрого перехода (Grid-каталог номеров вопросов 1..N) с цветовой индикацией статуса: не начат, решен верно, допущена ошибка.
  - Фильтры: «Все», «Только с ошибками», «Нерешенные».

### Шаг 2.2. Механика проверки, аналитика ошибок и LocalStorage
- **Интерактивный ответ и разбор:**
  - При выборе варианта: аккуратная фиксация выбора, мягкая подсветка статуса (спокойный графитовый акцент для верного и деликатный приглушенный для неверного).
  - Автоматическое раскрытие блока **«Методологический разбор»**:
    - Полное математическое/теоретическое обоснование (`explanation`).
    - Анатомия ловушек (`distractor_explanations`): объяснение, почему именно другие 3 варианта являются типичными ошибками.
- **Автономный режим (Offline-First / Для метро):**
  - Подключение легковесного Service Worker (`sw.js`) с Cache-First стратегией: при первой загрузке сайт кэширует оболочку и оба JSON-файла тестов целиком. При потере сети в метро или туннеле всё продолжает работать без сбоев.
  - Сохранение прогресса: синхронизация ответов с `localStorage` в реальном времени (ID вопроса, выбранный ответ, статус, дата). Работает 100% оффлайн без обращений к серверу.
  - Мгновенное восстановление прогресса при перезагрузке страницы и кнопка «Сбросить прогресс» с подтверждением.

## Этап 3. Мобильная полировка, GitHub Actions и запуск с доменом

*Фокус этапа: финальное тестирование на мобильных устройствах, автоматизация CI/CD пайплайна через GitHub Actions и привязка персонального домена с SSL.*

### Шаг 3.1. Мобильная оптимизация и touch-полировка
- **Touch-тюнинг:** отключение 300ms tap-delay, корректная изоляция `:hover` стилей для тачскринов через `@media (hover: hover)`, чтобы карточки не оставались в псевдо-нажатом состоянии после клика.
- **Форматирование формул:** проверка адаптивности математических обозначений ($df, x̄, SE, p$-value) на узких экранах смартфонов без ломки строк.
- **PWA & Offline-First:** регистрация Service Worker, создание `site.webmanifest` и иконок (`apple-touch-icon`). Возможность установить сайт как нативное веб-приложение на главный экран телефона с `theme-color` (`#FAFAF8`).

### Шаг 3.2. Автодеплой на GitHub Pages и подключение домена
- **Репозиторий и CI/CD:**
  - Инициализация Git-репозитория и публикация в GitHub.
  - Создание workflow `.github/workflows/deploy.yml` для автоматической сборки и публикации в ветку `gh-pages` при каждом коммите в `main`.
- **Подключение собственного домена:**
  - Добавление файла `CNAME` с указанием целевого домена в корень сайта.
  - Настройка DNS-записей у регистратора (4 A-записи на IP-адреса GitHub: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` или `CNAME` для поддомена).
  - Включение принудительного HTTPS («Enforce HTTPS») в настройках GitHub Pages (сертификат Let's Encrypt выпускается автоматически).
